# 两分钟看懂：怎样搭建、使用和更新 AI 数字员工

**技术人员提供需求和规范，AI 生成员工项目；工程底盘组织执行，外部检查确认结果。规范变化后，可以保留团队修改并更新知识。**

## 一个已经验证的例子

团队想让 AI 处理一类重复工作：C++ 文件引用了错误的头文件路径，导致编译失败。

| 用户表达 | 当前工程会做什么 |
|---|---|
| “帮我做一个只修复头文件引用的员工。” | 技术人员整理需求、支持的源码接口和完成标准，模型生成员工代码、流程清单及说明。 |
| “这是项目规范。” | 在修复阶段把规范提供给模型，记录所使用的版本。 |
| “先修这个项目，再试另一个项目。” | 同一个员工读取不同源码目录和真实编译错误，提出补丁，外部编译与修改范围检查通过后才记成功。 |
| “规范改了，但别覆盖我们加的代码和说明。” | 预览影响，保留团队修改，只更新既有知识内容，生成新版本，再运行任务验收。 |

这是使用场景说明。当前操作入口是命令行；可以借助 AI 编程助手整理材料，仓库没有独立聊天产品，也不会自动猜出公司内部接口。

## 最后得到什么

- 可查看的员工代码、流程和规范文件。
- 修复候选、差异补丁，以及成功或失败报告。
- 更新影响清单和保留原版本的记录。

## 哪些结果已经跑过

**搭建验证通过**：真实模型生成的同一员工，完成两个不同源码项目的修复和独立验收。[第四阶段 Actions](https://github.com/TIMPICKLE/devops-agent-chassis/actions/runs/34020348896)

**维护验证通过**：同一账单输入，旧规范选择 v1 接口，新规范选择 v2；团队定制代码和说明保留，两个原有任务仍通过。更新过程没有再次调用模型，运行任务仍调用模型。[第五阶段 Actions](https://github.com/TIMPICKLE/devops-agent-chassis/actions/runs/34033606604)

目前只验证了小型公开源码案例和既有知识内容更新；公司完整构建、任意业务需求及实际节省工时还需接入验证。

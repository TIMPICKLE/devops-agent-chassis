# Roadmap v3：从需求到可运行的数字员工项目

更新：2026-09-06。开发分支：`feat/roadmap-showcase-v1`。本版替代近期实施顺序；历史规划保留在 [Roadmap v2](ROADMAP_V2.md) 和 [Backlog v2](BACKLOG_V2.md)，前三阶段代码与实测继续保留。

## 产品目标

**用户提供工作需求、项目材料和完成标准，得到可运行、可维护、可验证的 DevOps 数字员工项目。**

近期围绕需求输入 → 生成项目 → 员工处理实际源码 → 外部工具独立验收建设。装配时调用模型，与员工运行时调用模型，分别留证。协议、节点和测试数量不代替产品进展。

## 为什么调整

前三阶段补齐了验收、知识消费、模型适配和证据，但实测主要是小型公开案例。旧 Live Assembly 允许生成确定性分类器；运行 Showcase 又使用预先编写的装配。两者尚未串成产品承诺的完整证据。第三阶段的执行异常与计量缺项仍保留，不通过改写历史结果美化进展。

## 交付顺序

| 阶段 | 用户能做什么 | 退出条件 | 状态 |
|---|---|---|---|
| P1 可运行项目 | 用需求和接口约定生成员工，指定自己的源码运行 | 生成物在新进程启动，运行期确实调用模型，生成代码之外的工具独立复核 | 本轮实施 |
| P2 业务变化更新 | 改规范或增加任务类型，局部更新项目 | 说明影响节点/知识，保留用户修改，新旧任务回归通过 | 待实施 |
| P3 企业接入与复用 | 接入现有代码治理/构建系统，装配第二类员工 | 实测真实任务采纳、接入/调试/人工复核时间 | 待实施，依赖业务材料 |
| P4 公平比较与展示 | 同条件比较现成执行器＋脚本＋CI与底盘 | 固定任务、知识、工具和验收，呈现收益和限制 | 待实施 |

P1 首个任务选 C++ 引用相关构建失败修复。项目接受本地源码目录和编译单元，读取真实编译错误，输出候选与 patch。CI 使用公开源码项目复现，**不称为公司生产任务或私有保留集**。运行入口必须可换目录/文件，生成器不能包含固定正确补丁。

## P1 的交付合同

- 输入：自然语言需求、源码接口、完成标准与知识文件；缺失时返回需要补充的字段。
- 输出：AI 生成员工代码、节点与知识绑定清单、运行说明；保留需求和生成证据。
- 执行：生成项目由共享运行入口启动，复用既有底盘、适配器和工具。
- 验收：独立重新编译候选，检查原文件、修改范围与 patch；成功必须有真实运行期模型证据。
- 泛化检查：在生成后才提供的另一源码项目中运行同一员工，不为第二输入重新生成。
- 失败分类：材料不足、生成失败、无法启动、模型异常、候选不合格分别记录，不退回模拟模式。

初版员工项目依赖本仓库固定版本的 SDK/参考模块，不承诺生成任意业务系统，不另造通用自然语言工作流语言。

## 取舍

保留小底盘、载荷边界、外层/内层分离、独立验收、知识回执、模型适配与 Actions。暂缓更多协议、孤立合成案例、无业务需要的多 Agent/A2A/DAG 并发、大型 UI 和安全平台扩展。

评测围绕产品问题：生成物能否运行？换材料后是否仍有效？用户要修多少代码？第二个员工是否更易接入？用量缺失必须展示，不以字符数代替费用。

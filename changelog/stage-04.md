# 第四阶段：需求生成项目，再由生成的员工完成任务

当前路线：[Roadmap v3](../roadmap/README.md)。分支：`feat/roadmap-showcase-v1`。

| 功能 | 用户得到什么 | 状态 |
|---|---|---|
| N01 产品路线调整 | 转向需求、生成、运行和独立验收；旧路线可追溯 | 文档已写入 |
| N02 需求驱动生成 | 生成员工代码、节点/知识清单和说明，缺失信息可解释 | 真实模型生成、来源检查与启动通过 |
| N03 源码构建修复 | 指定源码目录与编译单元，真实调用编译器和模型；可一次比较多个文件 | 两个源码输入真实运行通过 |
| N04 双阶段验收 | 同一生成员工处理不同源码输入，分开记录生成与运行调用 | 两个候选均通过外部重新编译和证据核验 |

公开源码验收不等于公司生产任务；企业接入、业务变化更新与脚本收益比较仍为后续里程碑。

运行入口与完整说明：[生成员工项目](../docs/GENERATED_EMPLOYEE_PROJECT.md)。

本轮复用底盘、ScopedKnowledge、运行期模型适配器、ReAct 客观停止与证据格式，新增能力放在 `employee_factory/` 与 CLI，没有把业务逻辑放进核心包。生成物选择节点接线，共享模块提供真实文件工具和独立编译判据。

本地新增检查涵盖：材料缺失不调用模型、生成接口合同、生成请求不包含后续源码、生成代码实际启动、真实文件读取/编译、第二个不同输入、删除业务代码绕过编译被拒绝、生成物变更使来源记录失效。模拟调用不算 live 实测。

本地 Python 3.12 完整回归 **185 passed**；本轮新增 8 个测试用例。文档相对链接已核对。模拟调用只验证实现，下面单独列出真实模型结果。

## 测试与复核中处理的问题

- 保留默认单调用下 Anthropic 原有错误文字，避免既有失败报告检查发生回归。
- 参数按每个调用分别深拷贝，避免共享列表等嵌套参数在多个工作线程之间串扰；记录保留传入参数，而不是工具修改后的值。
- 新增线程池部分提交失败测试：包括任务已入队但 Future 尚未返回的情况，已启动调用仍等待结束并完整记账；新增实际任务重试的预算测试，失败尝试不能重置动作额度。
- Connector ID 避免与模型调用 ID 碰撞；RecordingObserver 与可移植证据均携带批次关联字段。
- 默认单调用的观察结构保留原样，避免无关的参数重复回喂扩大旧任务输入；批量调用增加关联参数。

## 复现与使用

```bash
uv run --offline --no-project --with 'mcp>=2.1,<3' --with pytest --with jsonschema pytest tests/ -q
python examples/06_parallel_tools.py
python examples/04_swap_payload.py
```

上面的 `--offline` 依赖本地已缓存测试依赖。常规环境可按仓库说明安装依赖后运行 `python -m pytest tests/ -q`。

在原 CLI 命令后追加 `--max-parallel-tools 4`，并确保所选工具注册时声明 `parallel_safe=True`。默认每批上限 8、任务工具动作上限 64；详见 [并行调用使用说明](../docs/PARALLEL_TOOLS.md)。

## 边界

只有显式声明线程安全、相互独立且不修改共享 RunContext 的普通工具可组成批次；contextual 工具及未声明的工具必须单独调用。声明并行安全不授予任何权限，工具内部原有 PermissionBoundary 检查继续生效。并行批次不承诺事务回滚，一项失败不会撤销已完成的兄弟调用。

线程无法安全强杀；工具/Connector 需自行设置 I/O 超时。为避免清理竞态，底盘等待整批已提交动作结束，不做工具自动重试。只优化独立工具的等待时间，不保证 CPU 密集任务或具体企业任务的加速比。本次不修改 Hermes、本机配置及原始企业测试附件。

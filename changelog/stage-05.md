# 第五阶段：数字员工在规范变化后继续可用

分支：`feat/roadmap-showcase-v1`。对应 [Roadmap v3 / N05](../roadmap/BACKLOG.md)。

| 功能 | 用户价值 | 当前验证 |
|---|---|---|
| N05a 更新预览与版本化 | 说明知识和节点影响，保留人工修改，不覆盖原项目 | CI 与真实项目更新通过；更新 0 次模型调用 |
| N05b 变化后的行为与回归 | 员工按新规范改变结果，同时保持旧任务能力 | 同输入 v1→v2 行为变化、两个旧任务与独立验收均通过 |

使用入口：[更新员工项目](../docs/EMPLOYEE_PROJECT_UPDATES.md)。本轮未扩展安全平台，也未改动零依赖核心。

## 功能回顾 N05a

- 当前缺口：第四阶段生成项目依赖冻结文件，用户修改知识或代码后无法直接沿用来源记录。
- 本轮选择：知识内容更新采用确定性预览和版本化，不为这种更新调用模型重写项目。工作副本中的员工代码、说明与自定义文件按字节保留；元数据、流程清单变化或知识双方冲突则阻止更新。
- 比赛价值：展示数字员工的持续维护，而非一次生成。影响清单依据显式绑定与节点角色，不声称通用自然语言影响推断。
- 实用性边界：只支持既有知识文件内容变化；新任务接口、节点或工具变化需要后续适配。人工代码修改会保留，但正确性仍需运行验收。
- 动态调整：暂缓自动改代码和复杂合并，优先验证规范变化是否改变真实输出。

## 功能回顾 N05b

- 当前缺口：复制知识文件、甚至编译成功，都不能单独证明员工理解了新规范。
- 本轮选择：同一个账单输入有两个都能编译的接口版本；旧知识要求 v1，新知识要求 v2。独立验收检查实际选用路径，再对 pricing、scheduler 两个旧任务回归。
- 比赛价值：给出“规范更新 → 运行行为变化 → 旧能力保留”的可检查证据；区分更新成本与运行成本。
- 实用性边界：公开小型迁移案例不是企业生产数据或成功率统计。人工修改由 CI 模拟，实际保留情况通过文件内容核对。
- 后续取舍：这条闭环通过后优先接入真实构建命令与业务验收材料，不继续扩充相似的合成案例。

## 实测后的项目回顾与动态规划

1. **已得到的产品证据**：既能生成可运行项目，也能在知识变化后保留定制并验证行为变化。继续复用小底盘与既有模型适配器，这次没有新增核心依赖。
2. **不能夸大的部分**：这只是既有知识内容更新；不支持任意需求语义分析、工作流重写或通用三方代码合并。一轮公开样例不是成功率或成本优势的统计证据。
3. **下一优先级调整**：先把固定的单编译单元检查接到实际项目的构建配置/命令和业务验收，再考虑第二员工与横向对照。真实接入需要项目材料；不凭空编造接口或节省工时。
4. **完成判据延续**：后续每项功能仍单独记录“解决的用户问题 → 实测证据 → 剩余限制 → 继续或调整的决定”，不以节点、协议和测试数量代替业务价值。

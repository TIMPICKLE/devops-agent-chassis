# 第三阶段：项目知识驱动的配置修复

本阶段优先实现前瞻性与实用性。开发分支：`feat/roadmap-showcase-v1`。

| 功能 | 用户得到什么 | 验证 |
|---|---|---|
| S3-01 按任务与阶段注入多份规范 | 同时匹配项目、环境与当前阶段；每份文档单独记录版本、内容 hash 和消费回执 | 范围匹配、阶段切换清空快照、预算遗漏测试 |
| S3-02 项目规范驱动的配置修复 | 四个实际节点生成 JSON 与 patch；按项目容量和环境规则验收，保留无关字段 | 配置计算、独立验收、错误候选修正、模型请求检查 |
| S3-03 冻结输入的知识对照实验 | 四案例 × 三策略 × 重复次数；保存逐次证据和失败，独立重算结果 | 24 个 live 试次证据核验通过；none 组有 4 次执行异常，整体 live 门禁未通过 |

## S3-01 · ScopedKnowledge

新增通用 `ScopedKnowledge`，通过 `task_scope` 匹配任务字段、`fact_scope` 匹配流程显式写入的阶段。多个 provider 可同时命中，兼容已有调度器、模型适配器和证据格式，无新增底盘依赖。

这是确定性文档路由，不是向量检索。业务装配负责声明匹配规则和文档优先级；底盘不会根据节点名字猜测需要什么知识。缺失字段不匹配；阶段切换后重新收集会清空旧快照；预算不足的文档通过回执可见。

## S3-02 · 四节点配置工作流

新增 `ConfigSource / ConfigCriteria` 载荷，共用已有模型适配器、工具与停止机制。实际流程为 prepare → select_context → repair_config → verify_config；模型按项目与环境规范修改五个字段，保留其余配置，最后独立验收。只产出本地配置与 patch。

## S3-03 · 可复现知识对照

新增冻结公开案例、随机顺序的 routed / full / none 实验和独立核验器。每个试次重新装配，首次请求前冻结输入和模型参数；逐次保存报告与失败产物，显示未完成分母。执行异常单列，不能作为知识价值证据。基线不合格是实验结果；按需注入不合格或执行异常使运行门禁失败。

使用方式与技术细节：[项目规范到部署配置](../docs/CONFIG_POLICY_WORKFLOW.md)。四个公开合成任务不是未见保留集，也不宣称优于确定性脚本。

## 真实模型结果 · 2026-09-06

[Live job 与逐试次日志](https://github.com/TIMPICKLE/devops-agent-chassis/actions/runs/34005810091/job/101412719226)。使用 `glm-5.3-flash`、Anthropic 兼容端点，seed=42，repeats=2，每试次最多 2 次调用；四个案例 × 三策略 × 两次重复，共 24 次运行、32 次实际模型调用。

| 上下文策略 | 通过 / 计划 | 执行异常 | 模型调用 | 接口报告的输入 / 输出 token | 累计注入字符 |
|---|---|---:|---:|---|---:|
| 按需 routed | 8 / 8 | 0 | 8 | 4700 / 5187 | 2564 |
| 全量 full | 8 / 8 | 0 | 8 | 2912 / 4600 | 5144 |
| 不注入 none | 0 / 8 | 4 | 16 | 未完整获取，不能合计 | 0 |

按需与全量的 16 次成功运行均只调用模型一次。两组均通过配置判据与四节点轨迹检查。按需消费的文档正文更少，但这不是费用降低的证明。

无知识组中，4 次为未通过验收，另 4 次为执行异常；其中 trial-003 的用量不完整。当前日志没有逐项展开异常类型，不能将这 8 次失败全部归因于缺失知识，也不能将异常说成额度不足。失败原始记录保留在 artifact 中。

输入 token 需要谨慎解读：full 组前四次记录为 716，后四次为 12。现有适配器未保存缓存读取 / 写入 token 等分项，无法据此解释差异、校正完整输入量或计算真实费用。本轮**不宣称 routed 更省钱**。后续应补齐缓存计量与错误类型摘要，再做成本比较。

独立核验步骤成功：`Verified 24 trials: frozen inputs, config oracle, patches, nodes, context and usage`。它确认产物与报告相符，不把失败记录变成成功。

[下载冻结计划、24 份运行证据、候选配置与 patch](https://github.com/TIMPICKLE/devops-agent-chassis/actions/runs/34005810091/artifacts/9981048128)。名称 `config-policy-live-34005810091-1`，保留至 2026-09-20；当前环境无法取回 ZIP 做额外人工检查，以上数据来自 Actions 日志及其独立核验结果，未声称已逐份人工复查压缩包。

本轮支持的结论：工程底盘能够在这四个受控合成配置任务中，按阶段向模型提供项目专属规则，并生成通过独立验收的配置。样本公开且很小，不代表企业生产成功率，也不证明优于脚本。

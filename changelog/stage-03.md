# 第三阶段：项目知识驱动的配置修复

本阶段优先实现前瞻性与实用性。开发分支：`feat/roadmap-showcase-v1`。

| 功能 | 用户得到什么 | 验证 |
|---|---|---|
| S3-01 按任务与阶段注入多份规范 | 同时匹配项目、环境与当前阶段；每份文档单独记录版本、内容 hash 和消费回执 | 范围匹配、阶段切换清空快照、预算遗漏测试 |
| S3-02 项目规范驱动的配置修复 | 四个实际节点生成 JSON 与 patch；按项目容量和环境规则验收，保留无关字段 | 配置计算、独立验收、错误候选修正、模型请求检查 |
| S3-03 冻结输入的知识对照实验 | 四案例 × 三策略 × 重复次数；保存逐次证据和失败，独立重算结果 | 计划、产物、消费记录、汇总一致性检查；Actions 待补 |

## S3-01 · ScopedKnowledge

新增通用 `ScopedKnowledge`，通过 `task_scope` 匹配任务字段、`fact_scope` 匹配流程显式写入的阶段。多个 provider 可同时命中，兼容已有调度器、模型适配器和证据格式，无新增底盘依赖。

这是确定性文档路由，不是向量检索。业务装配负责声明匹配规则和文档优先级；底盘不会根据节点名字猜测需要什么知识。缺失字段不匹配；阶段切换后重新收集会清空旧快照；预算不足的文档通过回执可见。

## S3-02 · 四节点配置工作流

新增 `ConfigSource / ConfigCriteria` 载荷，共用已有模型适配器、工具与停止机制。实际流程为 prepare → select_context → repair_config → verify_config；模型按项目与环境规范修改五个字段，保留其余配置，最后独立验收。只产出本地配置与 patch。

## S3-03 · 可复现知识对照

新增冻结公开案例、随机顺序的 routed / full / none 实验和独立核验器。每个试次重新装配，首次请求前冻结输入和模型参数；逐次保存报告与失败产物，显示未完成分母。执行异常单列，不能作为知识价值证据。基线不合格是实验结果；按需注入不合格或执行异常使运行门禁失败。

使用方式与技术细节：[项目规范到部署配置](../docs/CONFIG_POLICY_WORKFLOW.md)。四个公开合成任务不是未见保留集，也不宣称优于确定性脚本。

Actions 与真实模型结果将在完成运行后补入，当前不声明 live 验证已通过。

本地 Python 3.12 完整回归：177 项通过；本阶段新增 17 项测试。12 个离线试次全部完成，独立配置与证据核验通过。离线没有模型调用，token 为未知，不算模型成功率。

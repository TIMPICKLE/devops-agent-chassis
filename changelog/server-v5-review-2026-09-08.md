## 问题归属与处理

| 报告内容 | 核对结果 | 本次处理 |
|---|---|---|
| 未声明安全工具时，warning 暗示自动保持单调用，实际却拒绝批次 | **底盘告警缺陷**。`every action will stay single-call` 容易被理解为自动降级；执行器实际按安全合同拒绝整批 | 修正 `validate_react_alignment()` 返回的提示，明确单调用仍合法、不安全批次零执行，无自动串行或取第一个调用；给出单调用配置与经过核验的并行声明两条路径 |
| `parallel_safe` 是本次版本新增加的要求 | **历史归因不准确**。报告引用的旧版 `757992e` 已有 ToolBox 安全声明及批次检查，T2 后诊断更明确 | 保留现有契约；不能用删除预检修复调用方漏声明的问题 |
| `stream=False` 导致某网关不可用 | **现有能力限制，具体失败因果未证实**。参考传输只读完整 JSON，没有 SSE 解析；附件没有该网关失败响应或配置依据 | 补充接入边界。不增加只有布尔开关、没有工具参数重组与中断处理的伪流式支持；流式能力仍未实现 |
| 访谈流程没有强制执行、需要新增 `assemble_employee.py` | **混淆工作指导与运行合同**。该 CLI 已存在，受支持需求缺材料会返回 `needs_input`，但不会强制任意外部助手逐项对话 | 说明受限 CLI 与通用装配 Skill 的区别，保留已有接口 |
| 前两次失败一定由推理 token 或预算不足导致 | **证据不足以确定原因**。报告描述传输超时，但附件只有成功轮次的完整调用记录，缺少对应失败证据和推理用量明细 | 文档说明按调用核对超时、输出预算和服务端记录；不根据模型名称或汇总错误推断根因 |
| Key 脱敏行为与任务路径前缀重复 | **运行环境/业务接入问题**，不属于底盘公共机制 | 本次不修改服务器或业务载荷 |
| 成功运行设置并发 4 | **不代表实际并发**。随附证据 `execution.batches=[]`、`parallel_observed=false`；三次模型调用成功 | 保留真实观察，不把该次运行称为并行性能验证 |
| 最终成功说明异味已修好 | **业务判据不足以支持该结论**。报告将完成标准限定为文件内容变化，证据未提供编译或重新扫描验收 | 说明 diff 只证明变化；具体业务应接入声明/引用、编译或扫描检查，底盘不硬编码这些业务规则 |

## 修复与兼容性

- 仅修改适配层装配提示，不改变 ReAct 执行、协议参数、安全声明、默认并发或重试策略。
- 没有安全工具但只执行单调用的装配仍合法，因此不将提示升级为无条件装配错误。
- 将并发设为 1 是选择单调用合同；模型仍返回批次时也会拒绝，不能把这个选项理解为自动适配不合规响应。
- 测试覆盖自定义 decider 和原生 OpenAI 适配器的合成批次响应：零工具执行、正确诊断以及失败请求用量保留；原单调用测试改为实际调用工具。
- 同步 [并行说明](../docs/PARALLEL_TOOLS.md)、[模型接入边界](../docs/MODEL_COMPATIBILITY.md)、[技术演示](../docs/TECHNICAL_USE_CASE.md)、README 与当前状态导航。

# 图解用户旅程重写 · 2026-09-06

## 快速了解这次变化

重写[领导与评阅者使用案例](../docs/LEADERS_USE_CASE.md)：由简短能力摘要改为一个完整用户旅程，说明“我怎样提出需求、每一步拿到什么、如何判断结果、以后怎样复用和更新”。本次修改文档与导航，不增加运行功能。

| 变化 | 对评阅者的帮助 |
|---|---|
| 七步交互：需求、知识、生成、运行、验收、复用、更新 | 按用户实际决策顺序理解整个项目 |
| 四张 Mermaid 图：总览、生成分支、运行反馈、更新验收 | 看清输入与产物、失败分支及新旧任务检查 |
| 每一步对应实际文件、用户确认点和下一步 | 区分员工项目交付与单次任务完成 |
| 补充实际修复差异、节点职责和知识使用说明 | 理解模型与底盘分别做什么 |
| 保留两条真实 Actions 链路、调用数与归档入口 | 可以从场景介绍继续核对实测证据 |
| README 顶部与变更概览同步改名 | 直接找到完整使用过程 |

## 与当前实现的核对

- 依据 `employee_factory/`、生成/运行/验证/更新命令、两条工作流及第四、第五阶段记录核对交互和产物。
- 示例对话明确为讲解用途；当前是助手协助加命令行入口，缺失材料检查是字段级检查。
- 节点确实由模型装配，首版限定线性 3–8 节点；工具与客观验收复用既有实现。
- 区分生成成功、运行成功、外部验收，以及“编译通过”和“业务规范满足”。
- 更新仅覆盖既有知识内容，保留人工文件不代表程序语义已验证；仍需新旧任务运行。
- 公开案例、固定单编译单元检查、依赖兼容仓库代码、归档期限及企业场景待验证均保留说明。
